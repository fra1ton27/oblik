# **ТЗ: сайт дизайнерской мебели (RU / EN / SR)**
Oct 20, 2026 · @Damir
## **1. Цель и рамки проекта**
Нужно сделать многостраничный трёхъязычный (RU / EN / SR) сайт-магазин компании, которая проектирует, производит и продаёт дизайнерскую мебель для дома. В составе: каталог, посадочные страницы товаров, корзина, оформление заказа, личный кабинет и формы обратной связи. Мобильная версия прорабатывается для каждой страницы, включая технические.
**Бренд.** Название компании пока не задано. Используй рабочее имя «Oblik» (по-сербски «форма», по-русски «облик») и вынеси его в src/config/site.ts, чтобы заменить в одном месте. Логотип на старте: текстовый знак дисплейным шрифтом + маленький SVG-знак из шейпов дизайн-системы (раздел 4).
**Задачи сайта**
  - Показать мебель как предметы дизайна: крупные фото, спокойный ритм, выразительные, но ненавязчивые анимации.
  - Продавать: каталог с фильтрами → посадочная страница товара → корзина → заказ.
  - Принимать заявки на индивидуальное производство (свои размеры, ткань, отделка).
  - Удерживать клиентов: личный кабинет с заказами, избранным и адресами.
**Как работать с этим ТЗ (инструкция для Claude Code)**
1.  Сохрани ТЗ в репозиторий как docs/SPEC.md, а в корне создай короткий CLAUDE.md: стек, команды, правила кода, ссылка на SPEC.
2.  Работай по этапам из раздела 15. Не переходи к следующему, пока не выполнены критерии приёмки текущего.
3.  Перед этапом пиши короткий план, после него список сделанного и чем это проверено.
4.  Весь текст интерфейса берётся из словарей переводов. Ни одной захардкоженной строки в компонентах.
5.  Если в ТЗ нет ответа, выбирай самый простой вариант, оставляй комментарий TODO(spec): \<вопрос\> и продолжай.
6.  С сайтов-референсов берём только принципы движения и композиции. Их код, изображения, тексты и фирменные элементы не копируем.
**Вне рамок первой версии:** реальная онлайн-оплата (делаем адаптер-заглушку), интеграция со складом и учётной системой, мобильное приложение. Архитектура должна позволять добавить их без переделки.

## **3. Мультиязычность: RU / EN / SR**
Три языка равноправны: у каждой страницы есть три версии со своими URL, переведённым интерфейсом и переведённым контентом из CMS. Интерфейс берётся из словарей next-intl, контент из локализованных полей Payload.
|  |  |  |  |  |  |
| :- | :- | :- | :- | :- | :- |
| Код | Язык | \<html lang\> | hreflang | Письменность | Формат цены / даты |
| ru | Русский (по умолчанию) | ru | ru | кириллица | ru-RU: 1 290 €, 20 октября 2026 |
| en | English | en | en | латиница | en-GB: €1,290, 20 October 2026 |
| sr | Srpski | sr-Latn | sr | латиница (latinica) | sr-Latn-RS: 1.290 €, 20. oktobar 2026. |

**Роутинг**
  - src/i18n/routing.ts: defineRouting({ locales: \['ru','en','sr'\], defaultLocale: 'ru', localePrefix: 'always', pathnames }). Язык по умолчанию меняется в одном месте.
  - Все URL с префиксом: /ru/..., /en/..., /sr/.... Корень / редиректит по порядку: кука NEXT\_LOCALE → заголовок Accept-Language → ru.
  - Сегменты URL локализованы через pathnames, для русского транслитом (кириллица в URL кодируется и плохо читается). Полная таблица адресов в разделе 6.
  - Слаги товаров, категорий и коллекций тоже локализованы и генерируются из названия транслитом (диван «Облако» → divan-oblako, oblako-sofa, sofa-oblak).
  - src/proxy.ts: createMiddleware(routing) из next-intl/middleware. Matcher исключает api, admin, \_next, \_vercel и пути с точкой (файлы), иначе сломается админка Payload.
  - Навигация только через Link, redirect, useRouter из src/i18n/navigation.ts (createNavigation), не через next/link напрямую.
**Словари интерфейса**
  - messages/{ru,en,sr}.json, неймспейсы: common, nav, home, catalog, product, cart, checkout, account, forms, validation, success, errors, seo, footer.
  - Набор ключей во всех трёх файлах одинаковый, это проверяет pnpm i18n:check. Типизация ключей через AppConfig next-intl, опечатка в ключе даёт ошибку TypeScript.
  - Плюралы только через ICU: в русском one/few/many/other (1 товар, 2 товара, 5 товаров), в сербском one/few/other (1 proizvod, 2 proizvoda, 5 proizvoda).
  - Цены, числа, даты и размеры форматируются только через useFormatter / Intl, вручную строки не склеиваем.
  - Claude Code пишет тексты сразу на трёх языках, естественно, без кальки. Сербские строки пишутся латиницей с диакритикой (č, ć, š, ž, đ), не «c» вместо «č».
**Контент из CMS**
  - В payload.config.ts: localization: { locales: \[{ code: 'ru', label: 'Русский' }, { code: 'en', label: 'English' }, { code: 'sr', label: 'Srpski' }\], defaultLocale: 'ru', fallback: true }.
  - localized: true у всех текстовых полей: название, слаг, описания, alt картинок, SEO-поля, блоки посадочных. Цена, артикул, размеры и фото общие.
  - Если перевода нет, показывается русский текст, а в админке у записи видна пометка «нет перевода».
**Переключатель языка**
  - Десктоп: сегментированная пилюля RU · EN · SR в шапке и в подвале. Мобайл: внизу полноэкранного меню и в подвале.
  - Переключение оставляет на той же сущности: с /ru/mebel/divan-oblako на /sr/namestaj/sofa-oblak, с сохранением фильтров в query. Состояние корзины и сессии не теряется.
  - Письма клиенту уходят на языке, на котором оформлен заказ или отправлена форма (поле locale в заказе и заявке). Менеджеру всегда по-русски.
Сербская кириллица (sr-Cyrl) в первую версию не входит, но архитектура должна позволять добавить её четвёртой локалью.
## **4. Дизайн-система**
Концепция: структура 1minus1 в пастельном ключе. Берём их приёмы: огромная дисплейная типографика, пилюли-кнопки и чипы, цветные скруглённые карточки-секции, ступенчатые формы, наклонённые карточки. Заменяем их кислотный лайм и тёмный фиолетовый фон на спокойные пастели на тёплом молочном фоне. Пиксельные ступени превращаются в мягкие «террасы», напоминающие модульную мебель: полки, ступени, стеллажи.

### **4.4. Сетка, отступы, радиусы**
  - Контейнер до 1440 px. Колонки: 4 (до 767 px, поля 16 px), 8 (768–1279, поля 32 px), 12 (≥ 1280, поля 40 px), гаттер 16 / 24 px.
  - Шаг отступов 4 px: 4, 8, 12, 16, 24, 32, 48, 64, 96, 128. Вертикаль между секциями: 64 px мобайл, 128 px десктоп.
  - Радиусы: 8 px (поля), 16 px (карточки товаров), 32 px (большие карточки-секции, на мобайле 20 px), 999 px (пилюли).
  - Теней почти нет: глубина строится цветом и линиями 1 px. Исключение: мягкая тень у наклонённых карточек и дроуэров (0 24px 48px -24px rgb(43 36 51 / 0.18)).

## **5. Анимации и моушн**
Движение спокойнее, чем у референсов: те же приёмы, но без глитчей и резких сдвигов. Мебель двигается медленно и тяжело, интерфейс легко и быстро.

### **5.3. Витрина каталога и комплектов по мотивам a24.raviklaassens.com**
На референсе вертикальный скролл крутит горизонтальную 3D-дугу дисков на светлом фоне. Активный диск в центре и крупнее, соседние меньше и развёрнуты. Слева сверху панель с названием и таблицей фактов с тонкими линиями. Внизу две короткие цитаты со звёздами. Сверху выпадающий «Индекс» со списком всех позиций и счётчиком. При наведении диск обводится рукописным кругом. Там же прелоадер с процентами и плавный скролл. Стек референса: three.js, GSAP + ScrollTrigger + SplitText, Lenis.
Компонент Showcase (витрина) делаем так:
1.  **Объекты.** Вместо дисков пастельные круглые подиумы (шейп Disc) с вырезанным фото товара (PNG/WebP с прозрачностью). Цвет подиума задаётся у товара в CMS (один из акцентов палитры). Товар парит над подиумом с мягкой контактной тенью.
2.  **Раскладка.** Позиции стоят на дуге слева направо. Активная в центре в масштабе 1, соседние 0.7 и повёрнуты по Y на ±25°. Видно 3–5 позиций.
3.  **Управление.** Вертикальный скролл (секция закреплена ScrollTrigger, высота прокрутки = количество позиций × 60vh), перетаскивание, свайп, стрелки ← →, клик по соседней позиции. После остановки доводится до ближайшей позиции (snap). Активный товар медленно вращается на подиуме ±8°.
4.  **Инфо-панель (слева сверху).** Название модели в Cormorant Garamond, под ним таблица с линиями 1 px: коллекция, дизайнер, материалы, размеры, срок изготовления. Цена и кнопки «Подробнее» / «В корзину». При смене позиции текст уходит вверх и приходит снизу по строкам (SplitText).
5.  **Низ экрана.** Две короткие цитаты из отзывов с оценкой (или два ключевых преимущества, если отзывов нет) и счётчик 03 / 24.
6.  **Индекс.** Кнопка-счётчик в шапке витрины открывает компактный список всех позиций, активная выделена заливкой ink. Фон под списком затемняется, клик по пункту прокручивает дугу к нему.
7.  **Hover.** Вокруг подиума рисуется рукописный круг (DrawSVG, 600 ms), курсор превращается в пилюлю «Смотреть».
8.  **Переход в товар.** По клику активное фото плавно переезжает на место главного фото на странице товара (shared element, Flip).
9.  **Реализация.** R3F-сцена с плоскостями-текстурами (не 3D-модели), dpr не выше 1.5, текстуры до 1024 px. Чанк грузится динамически (ssr: false) после первой отрисовки.
10. **Фолбэк.** Та же дуга на CSS 3D-трансформах без WebGL. Включается, если нет WebGL, prefers-reduced-motion, navigator.deviceMemory \< 4 или ширина \< 768 px. Для скринридеров и SEO в DOM всегда есть обычный список ссылок на товары (визуально скрыт при активной витрине).
Где используется: режим «Витрина» каталога, блок «Комплекты» (пакеты предложений: гостиная, спальня, столовая) на главной и страница коллекций. Для комплекта на подиуме стоит композиция из нескольких предметов, в инфо-панели состав, цена комплекта и экономия.
### **5.4. Переходы и микровзаимодействия**
  - **Переход между страницами:** ступенчатая шторка цвета следующей страницы, 500–700 ms. Свой TransitionLink + провайдер: анимация закрытия → router.push → анимация открытия. Не ломать prefetch, кнопку «Назад», открытие в новой вкладке и фокус.
  - **Кнопки:** заливка протекает слева направо, на главной CTA слабый «магнит» до 8 px (только десктоп).
  - **В корзину:** миниатюра товара летит к иконке корзины (Flip), счётчик прокручивает цифру, открывается мини-корзина.
  - **Количество и суммы:** цифры перекатываются снизу вверх при изменении.
  - **Успешная отправка:** ступенчатый шейп морфится в галочку (MorphSVG), раздел 10.
  - **Карточка товара:** на hover второе фото проявляется и появляются уголки (Brackets).
### **5.5. Технические правила анимаций**
  - Все GSAP-анимации через useGSAP со scope, чтобы они очищались при размонтировании. Плагины регистрируются один раз в src/components/motion/gsap.ts.
  - Разное поведение по ширине через gsap.matchMedia(), а не через проверки window.innerWidth.
  - Lenis синхронизирован со ScrollTrigger (lenis.on('scroll', ScrollTrigger.update)). После загрузки шрифтов и картинок вызывается ScrollTrigger.refresh(). На тач-устройствах Lenis отключён, работает нативный скролл.
  - Анимируем только transform, opacity, clip-path. Никаких анимаций width, top, box-shadow на скролле.
  - prefers-reduced-motion: reduce: выключаются плавный скролл, параллакс, закрепление секций, прелоадер, шторка переходов и WebGL. Остаются простые появления до 200 ms.
  - Контент доступен без JS: анимируемые элементы не скрыты в SSR-разметке, стартовое состояние задаётся скриптом или классом js-ready.
  - Анимации не блокируют ввод: клик во время анимации сразу ведёт к результату. Цель 60 fps на среднем Android.

## **7. Каталог и посадочные страницы**
Каталог работает в двух режимах: «Витрина» (для вдохновения, по мотивам A24) и «Сетка» (для поиска конкретного товара фильтрами). Каждый товар имеет полноценную посадочную страницу, собранную из блоков CMS.
### **7.1. Страница каталога**
  - **Переключатель режима** «Витрина / Сетка» (сегментированная пилюля) хранит состояние в ?view=showcase|grid. По умолчанию: витрина на /katalog без фильтров, сетка на страницах категорий и при любом активном фильтре. В витрине товары с флагом featured.
  - **Демо-категории:** диваны и кресла, столы, стулья, хранение (стеллажи, комоды), кровати, предметы интерьера.
  - **Фильтры:** категория, коллекция, цена (двухсторонний слайдер + поля), материал (дуб, орех, ясень, металл, камень, ткань), цвет обивки/отделки (свотчи), ширина в см (диапазон), наличие («в наличии» / «под заказ»), дизайнер.
  - **Сортировка:** популярные (по умолчанию), новинки, цена по возрастанию, цена по убыванию.
  - **Вид фильтров на десктопе:** строка чипов быстрых фильтров над сеткой (как «Filter by» у 1minus1) + кнопка «Все фильтры», открывающая дроуэр справа. Активные фильтры видны чипами с крестиком и кнопкой «Сбросить».
  - **Состояние фильтров в URL** (?material=oak\&price=500-2000\&sort=new\&page=2): ссылкой можно поделиться, «Назад» работает. Результаты рендерятся на сервере. У каждого значения фильтра счётчик товаров, нулевые значения неактивны.
  - **Сетка:** 3 колонки ≥ 1280 px, 3 колонки на планшете в альбомной, 2 колонки на мобайле. Каждая 7-я карточка может быть редакционной (фото интерьера на 2 колонки со ссылкой на коллекцию).
  - **Пагинация:** 24 товара на страницу, кнопка «Показать ещё» + номера страниц ссылками для поисковиков.
  - **Пустой результат:** ступенчатая иллюстрация, текст, кнопка сброса и предложение «Сделаем на заказ».
**Карточка товара в сетке:** фото 4:5 с радиусом 16 px (второе фото на hover), чипы в верхнем углу («Новинка», «В наличии», «Под заказ 4–6 нед.»), сердечко избранного, название, коллекция подписью, цена («от ...», если есть варианты), до 5 свотчей отделки. Быстрое «В корзину» только у товаров без обязательного выбора варианта. Вся карточка кликабельна, но сердечко и кнопки остаются отдельными элементами для клавиатуры.
### **7.2. Посадочная страница товара**
Страница товара работает как посадочная под рекламу: верхний блок покупки фиксирован, ниже идут блоки из поля layout товара, порядок и состав меняются в админке. Блоки по умолчанию:
1.  **Покупка (фиксированный).** Десктоп: слева галерея скроллом (фото в маске-арке + ракурсы + детали), справа липкая панель: хлебные крошки, название, короткое описание, цена, выбор варианта (размер чипами, ткань/отделка свотчами с названием), количество, «В корзину», сердечко, срок изготовления/доставки, ссылка «Нужен другой размер?» (открывает форму заявки с подставленным товаром). Смена варианта меняет фото, цену, срок и ?variant= в URL.
2.  **История модели.** Большой заголовок, цитата дизайнера в Cormorant italic, 2–3 наклонённых фото в интерьере.
3.  **Материалы.** Карточки материалов с макрофото, происхождением и уходом (из коллекции materials).
4.  **Размеры.** Линейный SVG-чертёж с размерными линиями + таблица (ширина, глубина, высота, высота сиденья, вес). В EN рядом с см показываем дюймы.
5.  **Соберите комплект.** Товары той же коллекции с чекбоксами, итоговой суммой и скидкой комплекта, кнопка «Добавить комплект».
6.  **Доставка, сборка, гарантия.** Аккордеон из 3–5 вопросов (FAQ с разметкой FAQPage).
7.  **Отзывы** (если есть в CMS): наклонённые карточки с фото покупателей.
8.  **CTA «Сделаем под ваш размер»** на фоне blush с кнопкой открытия формы.
9.  **Похожие товары.** Карусель из той же категории.
Когда кнопка «В корзину» уходит за край экрана, снизу появляется липкая плашка: миниатюра, название, выбранный вариант, цена, кнопка. На мобайле она видна всегда после первого экрана.
### **7.3. Посадочная коллекции / комплекта**
Hero с огромным названием и видео/фото в арке, история коллекции, витрина (5.3) с предметами коллекции, блок комплекта (состав, цена по отдельности и цена комплекта, экономия, кнопка «В корзину весь комплект»), интерьерная галерея, CTA на индивидуальный заказ. Страница тоже собирается из блоков CMS.
## **8. Корзина и оформление заказа**

Сервер пересчитывает сумму перед созданием заказа. Если цена или наличие изменились, покупатель возвращается к оформлению и подтверждает новую сумму.
### **8.1. Состояние корзины**
  - У гостя корзина в Zustand с persist (localStorage, ключ с версией схемы). У вошедшего дублируется в коллекцию carts. При входе гостевая и серверная корзины сливаются (количества одинаковых позиций складываются).
  - Строка корзины: productId, variantId, qty, снимок цены и названия для показа. На странице корзины и при оформлении цены, наличие и переводы пересчитываются на сервере. Цене с клиента никогда не доверяем.
  - Если цена или наличие изменились, у строки показывается заметка («Цена обновилась», «Теперь только под заказ»). Снятый с продажи товар виден, но не участвует в сумме.
  - Валюта: цены хранятся в базовой валюте из siteSettings (по умолчанию EUR). Опционально вторая валюта для показа (например RSD) по курсу, заданному в админке. Деньги в коде в целых минимальных единицах (центах), не float.
### **8.2. Мини-корзина**
Открывается после добавления товара и по клику на иконку. Десктоп: дроуэр справа шириной 440 px. Мобайл: нижний лист на 90% высоты, закрывается свайпом вниз. Внутри: список позиций с количеством, подытог, кнопки «Оформить» и «Перейти в корзину». Фокус удерживается внутри, Esc закрывает, изменения объявляются через aria-live.
### **8.3. Страница корзины**
  - **Список позиций:** фото, название-ссылка, вариант (размер, ткань), срок изготовления, цена за единицу, степпер количества, сумма, «Удалить» и «В избранное». Удаление отменяется из тоста в течение 5 секунд.
  - **Итоги (липкая панель справа):** подытог, скидка комплекта, поле промокода (в MVP проверка по коллекции promoCodes), доставка «рассчитаем на следующем шаге», итого, кнопка «Оформить заказ», строка доверия (гарантия, сроки, способы оплаты).
  - **Ниже:** «Дополните интерьер», товары из тех же коллекций.
  - **Пустая корзина:** ступенчатый шейп, который собирается в силуэт пустой полки, заголовок «Здесь пока пусто», CTA «В каталог», 4 популярных товара, ссылка на избранное, если оно не пустое.
### **8.4. Оформление заказа**
Одна страница, три шага аккордеоном со степпером сверху. Заполненный шаг сворачивается в сводку с кнопкой «Изменить». Данные формы сохраняются в sessionStorage, чтобы не потерять их при случайном уходе.
1.  **Контакты.** Имя, телефон (с выбором страны, по умолчанию RS; проверка через libphonenumber-js), email. Ссылка «Уже покупали? Войти», вошедшему поля подставляются.
2.  **Доставка.** Способ: доставка по городу / по стране / самовывоз из шоурума (зоны и цены из siteSettings). Адрес (из сохранённых или новый), этаж и лифт, желаемая дата, опции «подъём» и «сборка» с ценой.
3.  **Оплата и подтверждение.** В MVP активен один способ: «Оплата после подтверждения менеджером (по счёту или при получении)». Способ «Картой онлайн» показан неактивным с пометкой «скоро». Комментарий, чекбокс согласия с условиями и политикой (обязателен), чекбокс рассылки (необязателен, выключен). Кнопка «Подтвердить заказ» с итоговой суммой.
Сводка заказа: на десктопе липкая колонка справа, на мобайле свёрнутая плашка сверху «Ваш заказ · 3 товара · 2 480 €», разворачивается по нажатию.
**Что происходит при отправке (Server Action placeOrder)**
1.  Валидация zod-схемой (та же, что на клиенте). Ошибки возвращаются по полям и показываются рядом с ними, фокус на первом ошибочном поле.
2.  Пересчёт цен, скидок, доставки и наличия по данным базы. Если итог изменился, заказ не создаётся: покупатель видит новую сумму и подтверждает ещё раз.
3.  Создание заказа в транзакции: номер формата OB-2026-000123, статус new, снимок позиций, locale, UTM-метки. Повторный клик не создаёт дубль (ключ идемпотентности в форме).
4.  paymentProvider.initiate(order): в MVP ManualPaymentProvider просто помечает оплату как ожидающую. Интерфейс PaymentProvider с методами initiate, confirm, handleWebhook лежит в src/lib/payments.
5.  Письма: покупателю на его языке (состав, сумма, что дальше), менеджеру по-русски со ссылкой на заказ в админке. Ошибка почты не отменяет заказ, она логируется.
6.  Очистка корзины и редирект на «Заказ принят» с номером и одноразовым токеном доступа (чужой номер без токена не открывает данные).
### **8.5. Страница «Заказ принят»**
Анимация ступеней, собирающихся в галочку. Заголовок «Спасибо, заказ принят», номер заказа крупно с кнопкой копирования, короткая сводка (позиции, сумма, доставка), таймлайн «что дальше» (звонок менеджера → подтверждение и оплата → производство → доставка). Для гостя блок «Создайте пароль, чтобы следить за заказом» (одно поле, email уже известен, заказ привязывается). Кнопки «В кабинет» / «Продолжить покупки». noindex, обновление страницы не ломает её.
## **9. Личный кабинет**
Покупатели авторизуются через отдельную коллекцию Payload customers с включённым auth (email + пароль, httpOnly-кука, подтверждение email, восстановление пароля). Админы и менеджеры живут в коллекции users и в кабинет покупателя не попадают.
### **9.1. Страницы авторизации**
  - **Вход:** email, пароль (с кнопкой показа), «Запомнить меня», ссылки «Забыли пароль?» и «Регистрация». После входа возврат на returnTo (только внутренние пути).
  - **Регистрация:** имя, email, телефон (необязательно), пароль от 8 символов с индикатором надёжности, согласие с политикой. Язык уведомлений = текущая локаль.
  - **Восстановление пароля:** шаг 1 — email (ответ одинаковый, есть такой аккаунт или нет), шаг 2 — новый пароль по ссылке из письма (токен живёт 1 час).
  - Ограничение попыток: 5 неудачных входов за 10 минут блокируют вход на 15 минут (встроенные maxLoginAttempts / lockTime Payload).
  - Оформление: форма на наклонённой карточке paper поверх секции lavender со ступенчатым фоном (как форма контактов у 1minus1). На мобайле карточка без наклона на всю ширину.
### **9.2. Разделы кабинета**
|  |  |
| :- | :- |
| Раздел | Что внутри |
| Обзор | Приветствие по имени, последний заказ со статусом, избранное (4 товара), активные заявки, быстрые ссылки |
| Заказы | Список: номер, дата, сумма, статус-чип, миниатюры. Детальная страница: таймлайн статусов, позиции, доставка, оплата, кнопка «Повторить заказ», связь с менеджером |
| Избранное | Сетка карточек, удаление, «В корзину». Гостевое избранное из localStorage переносится при входе |
| Мои заявки | Заявки на индивидуальный заказ: дата, тип, статус (новая, в работе, предложение отправлено, закрыта), прикреплённые файлы |
| Адреса | Список, добавить / изменить / удалить, адрес по умолчанию |
| Профиль | Имя, телефон, язык писем, подписка на рассылку, смена пароля, смена email (с подтверждением), запрос на удаление аккаунта и данных |
| Выйти | С подтверждением, без потери гостевой корзины |

Статусы заказа и их цвета чипов: Новый (mist) → Подтверждён (lavender) → В производстве (blush) → Готов к отправке (sand) → Доставлен (pistachio); отдельно Отменён (линия error). Смена статуса в админке отправляет покупателю письмо на его языке (хук afterChange).
### **9.3. Навигация и доступ**
  - Десктоп: левое меню разделов + контент справа. Мобайл: горизонтальный скролл чипов-разделов под шапкой, активный чип прокручивается в видимую область.
  - Все страницы кабинета динамические, проверка сессии на сервере в layout раздела. Неавторизованный пользователь уходит на вход с returnTo.
  - Access control Payload: покупатель читает и меняет только свои заказы, заявки, адреса и профиль. Проверяется тестом: чужой ID заказа даёт 404.
## **10. Формы и технические страницы**
Все формы отправляются через Server Actions, сохраняются в коллекцию inquiries и ведут на одну страницу «Спасибо» с текстом под тип формы. Менеджер получает письмо на каждую заявку.
### **10.1. Формы**
|  |  |  |  |
| :- | :- | :- | :- |
| Форма | Где | Поля (обязательные отмечены \*) | type |
| Обратная связь | Контакты, конец главной | Имя\*, телефон или email\* (хотя бы одно), тема (вопрос по товару / доставка / сотрудничество / другое), сообщение\*, согласие\* | contact |
| Индивидуальный заказ | «На заказ», модалка на товаре | Тип мебели\*, размеры (Ш×Г×В, см), материал, бюджет (диапазон), желаемый срок, файлы (до 5 шт., до 10 МБ, jpg/png/heic/pdf), описание, имя\*, телефон\*, email, удобный канал (телефон / WhatsApp / Viber / Telegram / email), согласие\*. С товара подставляется модель | custom |
| Вопрос по товару | Модалка на посадочной | Имя\*, телефон или email\*, вопрос\*, согласие\*; товар и вариант подставляются скрыто | question |
| Подписка | Подвал | Email\*, согласие\*. Успех показывается на месте, без перехода | newsletter |

**Правила для всех форм**
  - Одна zod-схема на клиенте и сервере, тексты ошибок из неймспейса validation на трёх языках. Ошибка показывается после ухода из поля и при отправке, связана с полем через aria-describedby.
  - Правильные type, inputmode и autocomplete (name, tel, email, street-address, postal-code). Шрифт полей не меньше 16 px, чтобы iOS не зумил.
  - Кнопка отправки: состояние загрузки, блокировка повторной отправки. При ошибке сети данные не теряются, показывается тост с кнопкой «Повторить».
  - Антиспам: скрытое поле-ловушка, минимальное время заполнения 3 с, лимит 5 отправок с IP за 10 минут. Cloudflare Turnstile подключается, если задан ключ в env.
  - В заявке сохраняются type, данные формы, locale, страница-источник, UTM, статус (new), связь с покупателем, если он вошёл. Файлы идут в media с проверкой MIME и размера на сервере.
  - После успеха редирект на /\[locale\]/spasibo?type=\<type\>\&ref=\<номер заявки\> (номер вида Z-2026-00042).
### **10.2. Страница успешной отправки «Спасибо»**
1.  Полноэкранная секция lavender. Ступенчатый шейп собирается по ступеням и морфится в галочку (до 1.2 с).
2.  Заголовок display «Спасибо\!» / «Thank you\!» / «Hvala\!», под ним текст под тип формы: для custom «Дизайнер изучит заявку и свяжется с вами», для contact и question «Ответим в ближайшее рабочее время». Срок ответа берётся из siteSettings.
3.  Номер заявки чипом с кнопкой копирования (если есть ref).
4.  Три шага «что дальше» на маленьких карточках.
5.  Кнопки «В каталог» (primary) и «На главную» (secondary), ссылки на мессенджеры и соцсети.
6.  Ниже блок «Пока ждёте — посмотрите коллекции» (карусель из 3–4 комплектов).
Фокус после загрузки ставится на заголовок, чтобы скринридер прочитал результат. noindex. Прямой заход без параметров показывает общий вариант без номера и не падает. Разсобранная для мобайла версия в разделе 11.
### **10.3. Остальные технические страницы**
  - **404** (not-found.tsx на уровне \[locale\] + корневой): огромное «404» из ступенчатых блоков, текст «Такой страницы нет, зато есть мебель», кнопки на главную и в каталог, мини-игра «Собери стеллаж» (nice to have).
  - **500 / ошибка** (error.tsx, global-error.tsx): спокойный текст, кнопка «Попробовать снова» (reset), контакты. Без технических деталей ошибки для пользователя.
  - **Техработы:** включается флагом в siteSettings, админка остаётся доступной.
  - **Политика конфиденциальности, условия, доставка и оплата:** страницы из коллекции pages с рич-текстом, оглавлением и датой обновления. Тексты — заглушки с пометкой «требует проверки юристом».
  - **Cookie-баннер:** карточка в правом нижнем углу (на мобайле снизу на всю ширину), кнопки «Только необходимые», «Принять все», «Настроить». Аналитика грузится только после согласия. Баннер не перекрывает кнопку «В корзину» и липкие плашки.

  - **Липкие нижние плашки** («В корзину», «Оформить», «Подтвердить») не дублируются и не накладываются на cookie-баннер. У страницы есть нижний отступ на высоту плашки.

### **12.2. Хуки и логика на сервере**
  - Автогенерация слагов транслитом из title для каждой локали, проверка уникальности. Смена слага создаёт 301-редирект (коллекция redirects или плагин @payloadcms/plugin-redirects).
  - Номера заказов и заявок из последовательности в БД, без гонки при одновременных запросах.
  - Смена статуса заказа пишет statusHistory и отправляет письмо покупателю. Отмена возвращает остатки.
  - Публикация или изменение товара, категории, коллекции или global вызывает revalidateTag для связанных страниц на всех трёх языках.
  - Шаблоны писем в src/emails (React Email или HTML-шаблоны) на трёх языках, стиль по дизайн-системе (milk, ink, lavender). Письма: заказ принят, смена статуса, заявка получена, подтверждение email, сброс пароля, уведомления менеджеру.
### **12.3. Рендеринг и кэш**
Главная, каталог, товары, коллекции и контентные страницы статические с ревалидацией по тегам из хуков CMS (generateStaticParams для всех локалей). Корзина, оформление, кабинет и страницы успеха динамические. Каталог с фильтрами рендерится на сервере по query, запросы к БД кэшируются с теми же тегами.
### **12.4. Демо-данные (pnpm seed)**
6 категорий, 3 коллекции (2 из них комплекты), 24 товара с 2–3 вариантами, 8 материалов, 3 дизайнера, 10 отзывов, админ из env, демо-покупатель с 3 заказами в разных статусах. Все тексты на трёх языках. Картинки: сгенерированные локально (sharp) пастельные плейсхолдеры с шейпами и названием товара, чтобы не зависеть от сети и чужих лицензий. Реальные фото загружаются потом через админку. Seed идемпотентен: повторный запуск не создаёт дублей.
### **12.5. Переменные окружения (.env.example)**
DATABASE\_URL, PAYLOAD\_SECRET, NEXT\_PUBLIC\_SITE\_URL, RESEND\_API\_KEY, MAIL\_FROM, MANAGER\_EMAIL, SEED\_ADMIN\_EMAIL, SEED\_ADMIN\_PASSWORD, TURNSTILE\_SITE\_KEY / TURNSTILE\_SECRET\_KEY (необязательно), S3\_\* (необязательно, для хранения медиа в prod), NEXT\_PUBLIC\_ANALYTICS\_\* (необязательно). Без ключа почты письма пишутся в консоль, чтобы проект запускался локально без внешних сервисов.
### **12.6. Деплой**
Dockerfile (Next.js output: 'standalone') + docker-compose.prod.yml с Postgres и томом для медиа. Альтернатива: Vercel + Neon Postgres + S3-совместимое хранилище. Миграции Payload применяются перед стартом. README описывает локальный запуск и деплой по шагам.
## **13. SEO, производительность, доступность**
Анимации не должны стоить скорости и доступности: целевые цифры ниже проверяются на мобильном профиле Lighthouse для главной, каталога, товара и корзины на трёх языках.
|  |  |
| :- | :- |
| Метрика (мобайл, Slow 4G) | Цель |
| Lighthouse Performance | ≥ 90 |
| Lighthouse Accessibility / Best Practices / SEO | ≥ 95 / ≥ 95 / 100 |
| LCP | ≤ 2.5 с |
| INP | ≤ 200 ms |
| CLS | ≤ 0.05 |
| JS на первой загрузке маршрута (gzip, без ленивого WebGL-чанка) | ≤ 200 КБ |

### **13.1. SEO**
  - Metadata API на каждой странице и локали: title по шаблону «{страница} — Oblik», description из SEO-полей CMS (или автоматически из shortDescription), @payloadcms/plugin-seo в админке.
  - alternates.languages с hreflang ru, en, sr и x-default (ведёт на язык по умолчанию), canonical для каждой локали. У товаров альтернативы строятся по локализованным слагам.
  - OG-картинки генерируются через next/og в фирменном стиле: фото товара на подиуме, название, цена, шейп «терраса». Шрифты с кириллицей подключаются и в OG.
  - sitemap.xml (все локали с xhtml:link-альтернативами) и robots.txt (закрыты /admin, /api, корзина, оформление, кабинет, страницы успеха).
  - JSON-LD: Organization + FurnitureStore (адрес шоурума, часы), WebSite, BreadcrumbList, Product + Offer (+ AggregateRating, если есть отзывы), FAQPage, ItemList для категорий.
  - Страницы каталога с фильтрами в query имеют canonical на страницу без фильтров, ?page=N индексируется.
  - Весь текст товаров и ссылки есть в SSR-HTML, витрина на canvas не скрывает контент от поисковиков.
### **13.2. Производительность**
  - Изображения только через next/image (AVIF/WebP, корректный sizes, размеры заданы). priority только у LCP-картинки страницы, остальные ленивые. Blur-плейсхолдер цвета sand.
  - Шрифты через next/font (self-hosted, только нужные сабсеты и начертания), прелоад только Unbounded и Manrope. Метрики фолбэка настроены, чтобы не было сдвигов.
  - three.js, R3F, Draggable/Inertia, MorphSVG грузятся динамически только на тех страницах, где нужны. Перед сдачей проверь бандл через @next/bundle-analyzer.
  - Прелоадер не задерживает LCP: контент рендерится под ним, прелоадер только визуально снимается.
  - Видео в hero: без звука, playsinline, постер-картинка, до 3 МБ, на медленной сети (navigator.connection.saveData) остаётся постер.
  - Карта шоурума и сторонние виджеты грузятся по клику (facade).
### **13.3. Доступность (WCAG 2.2 AA)**
  - Контраст по таблице из 4.1. Видимый фокус: кольцо 2 px lavender-600 с отступом 2 px на всех интерактивных элементах.
  - Всё доступно с клавиатуры: витрина (стрелки, Enter), Индекс, карусели, фильтры, дроуэры, свотчи, степперы, аккордеоны. Полотно с перетаскиванием имеет кнопки-стрелки.
  - Ссылка «Перейти к содержанию», семантические ориентиры (header, nav, main, footer), один h1 на страницу, иерархия заголовков без пропусков.
  - Изменения корзины и результаты фильтрации объявляются через aria-live="polite". Модалки и дроуэры на нативном \<dialog\> или с корректными role, фокус возвращается на инициатор при закрытии.
  - Декоративные шейпы aria-hidden, у фото локализованный alt. Иконки-кнопки с aria-label на текущем языке. Цвет не единственный носитель смысла (статусы с текстом).
  - axe-core в e2e-тестах на всех страницах из раздела 6: нуль нарушений уровня serious и critical.
### **13.4. Безопасность**
Секреты только в env, куки httpOnly + Secure + SameSite=Lax, заголовки безопасности в next.config (CSP, HSTS, X-Content-Type-Options, Referrer-Policy), санитизация рич-текста, проверка загружаемых файлов на сервере, rate limit на формы и вход. returnTo принимает только внутренние пути.

## **15. Этапы работы и приёмка**
Работа идёт в 12 этапов. Каждый заканчивается рабочим состоянием проекта: pnpm lint, pnpm typecheck, pnpm test и pnpm i18n:check проходят, а изменения закоммичены отдельным коммитом с понятным описанием.
